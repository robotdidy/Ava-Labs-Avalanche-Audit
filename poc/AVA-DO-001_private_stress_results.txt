AVA-DO-001 private-network stress validation

Date: 2026-08-12
Source: AvalancheGo commit be3f61b9caa04a1ff6684fffbc553baad757ceb6
Network: four-validator tmpnet, process runtime, local API only
API used: http://127.0.0.1:45169
Traffic boundary: no Mainnet, Fuji, public RPC, or public peer traffic

The stress runner was executed twice on the same private network. The
baseline used the pre-funded local EWOQ key and one owner per exported UTXO.
The attack case used the separate pre-funded local VMRQ key and 2,048 owners
per exported UTXO. Each case created 16 X-Chain exports, then issued one
C-Chain atomic import and one ordinary C-Chain transfer during the import.
Both cases completed successfully through the production wallet, mempool,
atomic import, and block-processing paths.

Interpretation:

The attack run confirms live local reachability through the production
atomic-import and mempool paths and records a larger aggregate C-Chain VM
verification value for the owner-heavy case. The metric counts differ between
the two runs, and acceptance timing includes consensus and scheduling work,
so those aggregate sums are not presented as an isolated per-transaction CPU
multiplier. Import confirmation was 2.122 seconds in the baseline and 2.227
seconds in the attack run. The ordinary transaction submitted during the
import was not delayed in the attack run (269.8 ms versus 2.09 s baseline).

This run therefore validates production-path reachability and the presence of
unpriced external work, but it does not establish a reproducible network-wide
delay, loss of access, or the program's separate 30-percent node-resource
threshold. The deterministic in-memory PoC remains the clean evidence for the
fixed 307-byte/11,230-gas import versus the 41,058-byte, 2,048-owner source
UTXO and the growing verification/removal cost.

Command used for each case (from the WSL AvalancheGo checkout):

    GOTOOLCHAIN=local CGO_ENABLED=1 go run ./cmd/atomic-accounting-stress \
      -uri=http://127.0.0.1:45169 -mode=attack -exports=16
